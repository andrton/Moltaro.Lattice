# S24R · Capacity wait and ownership cleanup

**Track:** refactoring · **Base:** 2381f3c4 · **Needs:** S24A

The [architect's three entries](../../refactoring.md#after-s24) cover registering the
ready child's wait after rollback, acquiring a single charged backing and releasing
parked dictionary bucket generations to the restoration boundary. The existing
budget, withdrawal and child replay contracts are the acceptance. In particular,
the releasing thread can signal an armed child, the paced retry survives a release
before registration, and close or cancellation ends the wait. Keep the order of
reserve, registration and publication, and keep the tables selected for restoration
with their original layout and byte charges.

Compare the affected writes with the exact S24A parent and a separately built
parent twin. The archived pre-S24 and S24 controls keep the earlier budget cost
visible. Use the existing suite and format check on both sides of the change.

The code change on `92bb5eac` removes 21 net source lines across three files.
Using the same body and decision census as S24A, those files went from 90 to 88
bodies and from 136 to 134 branching points. The independent review checked
both points in the registration race, finite retries, close, ordered child
replay and the dictionary restoration boundary.

A standalone .NET 10.0.15 witness used the exact parent and candidate budget
assemblies. Release before registration left the next waiter pending. Timeout
and cancellation left the same signal available for a subsequent wait. A
concurrent release after registration woke it, as did reusable space, native
release and close. Close before registration returned a completed task, and
release and close left the expected charge.

A .NET 10.0.15 experiment also checked the rejected charged-owner scope. An
exception filter on an injected registration failure saw 0 B after the
existing catch and 40 B with the scope. Both handlers then saw 0 B. The
success path retained 40 B. A cached typed factory allocated 88 B on first
use even when the subsequent reservation was refused. It allocated 0 B
across 1,000 warmed invocations.
