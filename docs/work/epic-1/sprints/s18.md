*What is built.*

1. **One stored form for a structure.** A compiled layout, a null bitmap, the fixed
   fields and the descriptors that close it, serves a root and the record of an element
   of a List. An owned value is flattened into its holder: no block and no hop; a nullable
   owned value has one presence bit and every field beneath it a null bit, and an absent
   one keeps its width with every byte zero.
2. **Lists in two forms.** A List whose elements hold no descriptor (fixed-width values,
   references by an integer or a Guid, nullable ones with their bitmap in the record) is
   stored as a Binary is: the Length of its descriptor is bytes, an element may continue
   in the next chunk, and what places, frees, retires, exports and imports a Binary serves
   it unchanged. A List whose elements hold descriptors (String, Binary, a nested List, an
   owned value with such) is records at one stride, whole records in a block, under a
   descriptor kind of its own whose Length is the count; its form is told by the kind,
   never by the length. A value of at most 64 bytes is inline in the block that holds its
   descriptor. Nothing sorts or merges.
3. **One walk.** One recursive visitor over the descriptors of a structure serves the
   free, the publication, the retirement with its text bytes, the counts, `EntityBytes`,
   the export and the audit. It descends only into Lists whose elements hold descriptors,
   and no deeper than the schema allows.
4. **A Reference** is a field of the type of its target's key: an integer at its width, a
   Guid, or text stored as a String is. It is null by its null bit and never looked up; a
   missing target is not an error. A key that is text is validated by the core as a
   String value is.
5. **An index over a path** resolves its stored field once, when the layout of the index
   is compiled; an absent owned value on the path gives a null part. The size of an
   entry part does not change.
6. **A child.** The wire carries the version of the layout, the root with its locations
   zeroed, then the values in preorder, with no offset between values. The check walks
   the whole input by the layout before anything is allocated: a count times a stride in
   64 bits against the bytes left, a kind against a count, null bits that agree, zero
   locations, inline spans inside their block, the total exact. One routine places what
   a child received, a forwarded write, a member of a batch and a local write.
7. **Copies.** A read by name gains owned values, Lists and references without a box for
   each element. A read by a class gets the binding of a record to a class for nested
   values, which does not exist today: under the protection the nested value is made in
   the form of a record, and the object is built from it outside the protection, so that
   no constructor and no setter of the application runs inside it.
8. **The bound at depth, the rule of Q55, the time limit that tests can drive, and L4**,
   as the notes above say. The refusals name a place as the validation names one today,
   by the type that declares the field and the field.
9. **Rules of the schema language**, checked when a database compiles its layouts at its
   open, `InvalidSchema` with the entity type named: the fixed part of
   an entity, its owned values included, fits one block; the record of an element of a
   List fits one chunk; an entity type is refused as not stored yet only when it holds a
   Map or a Set at any depth.

**Found after the close of S18, 24 November 2026: the state of an instance behind its fault.**
A red check of `arm64` on a pull request of documents (PR 59, merged with it by the
coordinator's mistake: a merge needs every check green, though `build` is the only check the
repository requires) showed
`ChildPublicationTests.Read_that_waits_for_a_publication_of_a_child_that_fails_ends_with_Unavailable`
fail once: both reads refused with `Unavailable`, then `State` read Ready, not Faulted. The
log is kept outside the repository. The cause, by reading and by a delay: `EngineDatabase.Fault`
marks the reads faulted first (`ReadEpochs.Fault`) and stores the state under the lock of
the state after it, then ends the waits for a position; on a child the first mark is made
under the lock of the writes in the publication's catch and the state is stored after the
unwind, a window of 17 to 67 µs (median 27), on a master 7 to 12 µs. It is the same on x64;
the runner was descheduled inside it. 800 runs on the workstation unchanged gave no failure;
a pause at that point failed the test 30 of 30 at 50 ms, 12 of 30 at 5 ms and 1 of 30 at
1 ms, always the same three rows (this test and both rows of
`WaitingReadTests.Read_that_waits_for_a_publication_that_fails_ends_with_Unavailable`, the two
tests that use `held.Fail()`); the eleven other assertions of `State == Faulted` follow an
awaited write outcome, given after the store. The contract's letter holds, but an
application told "the database is Faulted" by one call could read Ready on the next.
Decided by the planner on 24 November 2026, form (A): one point decides the fault. `State`
reads the fault mark of the reads as well as the stored state, and `ThrowIfNotReady` reads
`State`; the remarks of the Faulted state gain the sentence that once a read has reported
`Unavailable` for the fault, `State` is Faulted. It is a small change of behavior, of the
light track, with one reviewer at xhigh, and the first work of the next coordinator, before
S18R: the test first, with a pause at that point through the switch the engine tests
already have, failing before the change on a master and on a child; then the change; the
listings of a read by key and of a search showing no load added, since neither reads
`State`; the two tests that use `held.Fail()` unchanged and passing with the pause; and the
other way checked as well, that nothing reports work of a Ready instance done after `State`
reads Faulted. The ordering lane and these tests run on ARM64 in the next start of the
machine. It was seen again on x64 the same day, on a pull request of documents (PR 63, run
45362194937, the job `build`), in `WaitingReadTests.Read_that_waits_for_a_publication_that_fails_ends_with_Unavailable`
with the child, as the reading said it could be: not a defect of ARM64. Until the fix is in,
any pull request can fail on those three rows; its job is run again, and every sighting is
counted here. The fix is the first work of the next coordinator, before anything else is
merged.

**The form (A) fix** (24 November 2026, light track, coordinator 9).

- `State` checks the read fault mark before it reads the stored state, so a close still
  takes precedence. `ThrowIfNotReady` uses `State`. The planner confirmed that the
  existing guarantee covers a new write through a child set obtained earlier and the
  commit of an already assembled batch. The child sender could forward both while the
  follower unwound the failed publication. `Forwarder.Begin` now checks the same mark
  after cancellation and close, before it binds a session or queues a request. Admitted
  requests keep their existing outcomes.
- The first test commit, `e7f0eb1`, reproduced `Ready` after two waiting reads reported
  `Unavailable` on each role. The second, `70a6bf9`, showed a new entity on the master for
  both forms of the child's write while the child was paused at the mark. Both commits
  preceded the fix. Both original `held.Fail()` methods kept their assertions and passed
  all three rows with a 50 ms pause at the mark in an isolated build.
- The independent review took two rounds. The child write tests gained a fresh session
  that must stay unbound, so they catch admission even if the sender has yet to run. Two
  comments now describe the lock and retry rules. The hardest part to follow was the
  order across the read mark, the stored lifecycle state, the position clock and the
  sender. The second round closed every finding.
